# @hius/test-harness

[English](README.md)

Хелперы для тестов на реальных зависимостях — для собственного тестового
набора Hius-приложения. Те же строительные блоки, что использует и сам
фреймворк в своих тестах, обобщённые, чтобы не изобретать их заново в
каждом тестовом файле. Здесь ничто не мокается: реальное подключение к
Postgres, реальный HTTP-сервер, реальные (детерминированные,
только-для-тестов) ключи шифрования.

## `hasDb`

```ts
import { hasDb } from "@hius/test-harness";

describe.if(hasDb)("integration tests", () => {
  // ...
});
```

`true`, когда задан `DATABASE_URL` (например, из `.env.test`, который Bun
загружает автоматически при `bun test`). Используйте его для условного
запуска интеграционных тестов, а не для молчаливого пропуска в
неправильно настроенном окружении.

> **Осторожно с `describe.if()`:** тело callback-а describe выполняется,
> даже когда условие ложно — пропускаются только тесты/хуки внутри.
> Вызывайте `createTestDatabase()` внутри `beforeAll()`, а не напрямую в
> теле describe, иначе её ошибка «DATABASE_URL не задан» сработает
> независимо от условия `hasDb`.

## `createTestDatabase()`

```ts
const { sql, db, teardown } = createTestDatabase();
// ... используем sql/db ...
await teardown();
```

Открывает реальное подключение к `DATABASE_URL` и оборачивает его в
Drizzle (`drizzle-orm/bun-sql`, без привязки схемы — `db.select().from(table)`
работает с любой таблицей и без неё). Сразу бросает исключение, если
`DATABASE_URL` не задан, поэтому сначала проверяйте `hasDb` (где именно
его вызывать — см. предупреждение выше).

## `createTestKeyProvider()` / `testKeyBundle`

```ts
const provider = createTestKeyProvider();
const crypto = createCryptoEngine(provider);
```

Фиксированный, детерминированный тестовый ключ на 32 байта, обёрнутый в
`KeyProvider` — никогда не используйте его вне тестов. `testKeyBundle` —
сырой пакет ключа, экспортирован отдельно для тестов, которые сами
компонуют своего провайдера (тестам ротации ключей нужен *второй*,
отдельный пакет ключа рядом с этим — через
`createStaticKeyProvider(testKeyBundle, [otherKey])`).

## `createTestServer(routes)`

```ts
const server = createTestServer(routes);
const res = await server.fetch("/invoices", { method: "POST", body: "..." });
server.close();
```

Поднимает реальный HTTP-сервер на свободном порту, назначенном ОС
(безопасно для тестов, выполняющихся параллельно), и возвращает `fetch`,
привязанный к нему — настоящий цикл запрос/ответ через реальный роутер, а
не вызов обработчика внутри процесса, так что коды статуса, заголовки и
сериализация проверяются точно так же, как их увидел бы реальный клиент.
